## 3. Критерії готовності до випуску (Go / No-Go)

Критерії фіксуються **до** отримання результатів регресії.

| ID | Критерій | Поріг | Обґрунтування |
|---|---|---|---|
| **К1** | Критичність дефектів (безумовний) | `0` відкритих дефектів рівня `Blocker` та `Critical` | Для онлайн-банкінгу «ФінКит» критичні помилки у розрахунку кредитів, балансу рахунку або переказах коштів є неприпустимими. |
| **К2** | Покриття вимог | Покриття вимог `High` = `100%`, загальне покриття вимог `SRS-1.1` ≥ `75%` | Усі функціональні вимоги, інтерфейс та бізнес-логіка мають бути перевірені; непокритими допускаються лише нефункціональні вимоги (`P-`, `S-`, `D-`), що потребують інструментів навантаження або огляду документації. |
| **К3** | Pass Rate | Частка пройдених виконаних кейсів ≥ `90%` | Допускаються лише поодинокі дефекти рівня `Minor`/`Trivial` (`P3`), які не блокують основні фінансові операції клієнта. |
| **К4** | Відсутність регресії (безумовний) | `0` відкритих регресійних дефектів у модулі `v2` (переходів `Passed → Failed`) | Оновлення модуля бізнес-логіки не повинно ламати функціональність, яка стабільно працювала у версії `v1`. |
| **К5** | Повнота прогону | `100%` кейсів виконано (або кожен `Blocked` має обґрунтовану причину недоступності demo) | Для достовірного висновку мають бути перевірені всі заплановані сценарії; виняток можливий лише за тимчасової технічної недоступності зовнішнього середовища ParaBank, що фіксується в `regression-log.xlsx` з посиланням на Issue. |
